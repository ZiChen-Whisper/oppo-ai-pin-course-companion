# 本地课程管理

先读 [共同数据与索引派发规则](../../references/shared-workflow.md)。这是课堂回顾和课程信息管理共同使用的集中课程数据来源。

- 无具体操作：先从 list_courses 返回的 jobs 检查 awaiting_agent 请求并按共同规则派发；再调用本地 list_courses，按课程列出课程名称/别名、学期、教师、上课时间、主目录和额外目录、指定资料与备注、最近索引状态，调用 open_course_manager 并在 Codex 浏览器打开返回链接。资料多时先列目录结构和类型，再提供既有索引详情，不能谎称已列出全部文件。
- 首次实际调用、列表为空：打开空管理界面，再询问用户课程资料总目录、课程名称与路径；可由用户逐门添加。未经提供目录不遍历磁盘猜测，不自动把每个子文件夹都认成课程。
- “修改某门课程……”：读取集中信息，按指定范围编辑；明确的修改直接保存并读回，不额外要求同义确认。遇到同名课程先消歧。
- 更新资料索引：必须按共同规则派发 gpt-6-luna/high 子 Agent。目录和资料有变化时重新索引不覆盖手工分类/备注。默认仅列信息不强制刷新全部索引；课堂回顾由其过期策略触发。
- 指定教材与资料分类的用户选择优先于自动识别。可视化编辑保存的是中央台账，不是散落的各课程配置。

界面为 HeroUI React 资料工作台：课程侧栏、资料筛选/多选、用途与格式分离、分类依据及人工确认、主要教材设置，以及结构化课程设置。目录选择器不可用时允许粘贴完整路径；不假称所有自动分类都来自模型通读。人工指定保存在中央台账，索引更新不得覆盖。界面实现来自 oil-ui-pro 的工作区设计；维护时加载 oil-ui-pro 与 whisper-frontend，实际验证保存后重载和失败保留输入。


每次均在聊天给出统一课程入口（包括未执行索引、无变化或报错的情况）。页面含课程资料、课程笔记、课程信息和课程设置；笔记只读取既有产物，课程信息是飞书镜像。资料目录索引仍按共同规则派发，不把刷新笔记列表或读取课程信息当成教材索引更新。
