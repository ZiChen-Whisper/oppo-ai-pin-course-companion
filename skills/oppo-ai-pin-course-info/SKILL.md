# 课程关键信息管理

读 [共同数据、完整采集与飞书规则](../../references/shared-workflow.md)。首次实际调用时关联或创建飞书文档；创建插件时不建立私人文档。加载当前 lark-doc 技能，遵循从零创建、局部更新、完整回读流程；遇到认证问题按 lark-shared 处理。

## 每次调用

**课程事项以转录原文为主要证据，MCP 自动总结仅作检索参考。** 从原文及上下文提取并核对要求、日期、数字和限制条件；不得直接将摘要中的要求写成已明确通知。摘要与原文冲突以原文为准；无原文的摘要候选标“仅摘要，待原文核实”，不伪造原话，按共同证据规则处理后再决定是否写入。

1. 从中央台账取得全部课程和唯一飞书文档 URL。读取飞书文档全部已有记录（包括用户编辑与备注），不能只看最近一页或本地旧副本。
2. 按用户要求，两个 OPPO AI Pin 接口每次全历史分页读取，包含以往记录与原文，补齐原摘要可能后续更新的内容；按共同采集规则保存，不漏随口记。不要以“增量优化”为由省略用户要求的历史复查。
3. 提取与课程有关的考试/考核时间、地点、形式、范围、允许携带资料、作业内容、提交方式、DDL、分组、实验任务、报告要求、评分和其他教学通知。与既有课程名/资料交叉核对；无法确定课程的先列为待归属，不猜测写入某门课。
4. 核对原话、前后文和说话人。speaker=1 不自动等于教师；同学转述“老师说……”必须标“转述待确认”，不能因自动摘要措辞肯定就当正式通知。isHost 和重点标记只作为辅助。保留未知年份/模糊截止时间，必要时根据说话日期换算并明确这是推算。
5. 与飞书已有所有事项合并：多次提及同一作业追加来源；同名但不同作业不强行合并。“延期/改范围”作为关联变更记录，旧要求标记被替代而非删除。冲突并列并提示核实；用户确认/手工备注优先保留，不整篇覆盖。
6. 用 lark-doc 局部更新写入，回读验证条目、来源、保留的用户内容；失败不记成功。只要课程归属清楚，可自动记录带状态的信息，不反复为每条事项要求许可；课程归属不清则先询问。

## 文档组织

文档默认“OPPO AI Pin｜课程关键信息”。开头展示仍有效的近期事项、待确认事项；按课程维护完整记录与变更来源。每条有稳定事项 ID（本地维护，同步重试可识别）、课程、事项类型/名称、具体要求、原始日期说法与换算日期、状态、原话摘录、记录时间/说话人编号和会话 ID。缺失字段写未说明，不臆造。DDL 经过不自动等于作业已完成。

状态可用：待确认、已明确、已变更/被替代、用户确认完成。保留用户更正和确认信息，AI 不覆盖成人工未完成或反之。本地 data_root/course-info-sync.json 保存事项 ID、内容 hash、来源记录 hash、对应飞书 block ID 和最后成功同步时间（不含凭据）。只有 fetch 验证成功后更新；写入中断重试前先查远端是否已存在，避免重复插入。

交付本次新增、变更、待核实事项和飞书链接，明确实际读取时间范围与是否完整。只维护课程信息，不自动创建日历、任务或给他人发消息。
