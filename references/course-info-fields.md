# 课程事项字段 v1

每条事项对应一个独立飞书普通段落，类型与状态由固定选项维护，课程归属来自课程标题。课程名称、教师、学期、课表仍只在课程设置维护。

| 字段 | 规则 |
|---|---|
| 事项名称 | 必填，简短识别事项，不带 CC 标记 |
| 类型 | 考试／评分、作业、实验／报告、教学通知、变更／备注、其他 |
| 状态 | 待确认、转述待确认、已明确、已变更／被替代、用户确认完成；AI 不自动把过期变完成 |
| 具体要求 | 必填，内容、条件、否定与例外准确保留 |
| 时间说明 | 允许“下周”“未说明具体日期”等原始说法；换算要标明依据 |
| 明确截止时间 | 可选 ISO 本地日期时间，只有日期、时刻均明确时填写；截止不等于完成 |
| 地点、形式、范围、评分、允许资料 | 考试按实际原文填写，缺失留空；页面不把未知当事实 |
| 提交方式、分组、评分 | 作业及实验按原文填写，可含提交平台、文件格式、报告和组队要求 |
| 限制与待确认 | 记录缺失、口头举例、冲突、转述属性、变更关联事项 ID；不把示例变成正式评分规则 |
| 原话 | 必要原句，保留上下文，不用 MCP 摘要冒充 |
| 来源 | 记录 ID/hash、课堂日期、句子/分段下标及时间、说话人编号；教材来源另写文件章节/页码 |
| 原始记录 | 旧格式首次编辑时保留完整旧段落，只读；不删除未知字段和人工备注 |

实现使用 runtime/info_fields.py 作为标签、解析、选项和序列化的唯一来源。段落以 `[CC-INFO:v1]` 开头，字段用中文标签、冒号与值表示，字段续行缩进两个空格；原始记录始终最后。稳定去重 `[CC:…]` 继续由同步流程维护。页面 API entry 仅从同一 text 派生，不建立第二份独立结构化台账。

技能写入统一调用 `edit-info --input <JSON>`，参数 `{course_id, revision, id?, entry:{title,kind,status,requirements,timing,deadline,location,format,scope,submission,grouping,grading,materials,limitations,quote,source,original},section}`；仅 title/requirements/kind/status 必填，其余可省略。读取 course-info 的当前 revision；修改已有事项时在其 entry 上精确更新并保留 original，不吞掉字段；新增时不伪造原始记录。再 sync-info --course-id 提交并回读，同一条目两端变更仍走三方冲突。AI 可使用同一 serialize 输出供 lark-doc 局部更新，但不能手造另一套标签或 JSON 段落。

旧段落只做兼容解析展示，解析时不自动上传或覆盖飞书。富文本、含批注段落继续在飞书维护。来源与说明默认折叠，要求、状态及关键时间默认可见。
